# M1 — Weight extraction & activation capture

**Status: PASS.** Weight extraction verified by exact QKV reconstruction; the frozen eval corpus is built from the Pile; activation caches exist for all five models.

## 1. Weight extraction (`lib/models.py`)

`extract_weights(model)` returns `{(layer_idx, weight_type): tensor}` (detached float32) for every Q/K/V/O/MLP/LayerNorm/embedding matrix. The fused GPT-NeoX `query_key_value` is split **head-aware** (`split_fused_qkv`); `refuse_qkv` is its exact inverse.

- **#1-risk de-risked:** on pythia-70m, re-fusing each block's split Q/K/V reproduces the original fused matrix **bit-identically** (`test_extract.py`). Synthetic tests also guard against a naive third-split.
- **transformers 5.x note:** the output/unembedding head is `lm_head` (renamed from `embed_out` in 4.x); `EMB_OUT` reads it. Verified the module layout on the Spark before coding.

## 2. Frozen eval corpus (`lib/data.py` → `data/eval_tokens.pt`)

- **(10000, 128)** int64 tokens, **10.24 MB**, tokenizer `EleutherAI/pythia-70m` (shared across the suite).
- **Provenance: `monology/pile-uncopyrighted:train`** — the Pile is Pythia's own training distribution, so activations are in-distribution. Needed `zstandard` to decode the Pile's `.jsonl.zst` shards; without it the build silently falls back to C4 (logged).
- First **500** sequences reserved as the CKA subset (M2). The file is frozen — built once, never silently regenerated.

## 3. Activation capture (`lib/activations.py`)

Forward hook on every block captures its output hidden state; per layer we store mean-pooled + last-token vectors for all 10k sequences, and all token positions for the CKA subset — float16, under `data/activations/<model>/`.

- **Deterministic:** two capture runs are bit-identical (mean-pooled and full-token CKA) — `test_activations.py`.
- Shapes confirmed: e.g. 1.4b `mean_pooled (24, 10000, 2048)`, `cka_tokens (24, 500, 128, 2048)`.
