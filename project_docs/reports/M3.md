# M3 — Coarse projection (1.4B → 410M)

**Status: DONE, with the acceptance bar honestly NOT met zero-shot — and a mechanically-verified diagnosis of why.** The assembled projected model runs and generates deterministically, but it does not beat random init on perplexity. The assembly plumbing is proven bit-exact, so the failure is the projection *math* itself: dense basis mixing breaks the network's structured computation. This sharpens (rather than kills) the Paper-1 story — details below.

## 1. Target-free projection residuals (`experiments/m3_project.py`)

`W_hat = P_out · W_large · P_inᵀ` with size-relationship bases only (residual axis: global activation-PCA `P_res`; internal axes: SVD bases **shared between interacting weights** — Q/K one basis, V/O one basis, MLP_UP/DOWN one joint basis from `[UP, DOWNᵀ]`). Relative Frobenius error vs. the actual 410M weights, mean over 24 layers; `operator` = the fitted shared (A,B) diagnostic (peeks at the target = how linearly the sizes relate at best):

| Type | projection (target-free) | operator (fitted) |
|---|---|---|
| Q        | 1.471 | 0.658 |
| K        | 1.591 | 0.758 |
| V        | 1.390 | 0.804 |
| O        | 1.724 | 0.795 |
| MLP_UP   | 1.668 | 0.683 |
| MLP_DOWN | 1.723 | 0.686 |

**Reading:** every target-free error is **> 1** (worse than predicting zero) — the projected weights share almost nothing with the 410M's *particular* solution, confirming M2's activation-vs-weight gap at every layer. Even the fitted operator only reaches 0.66–0.80: at best ~30% of weight variance is linearly explainable across sizes with one shared map. (Design note: a *per-layer* fitted (A,B) is degenerate — around a full-rank W it can hit any target, error → 0 — so it was dropped; only the shared fit is meaningful.)

## 3. Mechanical verification (`experiments/m3_identity.py`)

Per the plan's debug instruction (suspect LayerNorm/QKV bugs first): rebuilding the 1.4B **from its own extracted weights with no projection** reproduces the real model's logits with **max |diff| = 0** — bit-exact. Extraction, QKV/bias split+fuse, embeddings, and LN plumbing are all correct. The quality loss is entirely the projection math.

## 4. Diagnosis: dense basis mixing vs. structured computation

A dense (rotation-like) basis change on any internal axis silently changes what the network *computes*, because every nonlinear/structured op in the block is tied to specific coordinates:

- **Rotary embeddings** act on fixed per-head dimension pairs → any head-space mixing distorts positions.
- **Attention is per-head** — our global 2048→1024 head-space basis mixes dimensions *across* heads.
- **GELU is elementwise** in the MLP hidden space: `GELU(Bx) ≠ B·GELU(x)`.
- **LayerNorm gains/biases are per-feature** in the residual stream — a rotated stream no longer matches any diagonal gain (this is why the projected-LN variant explodes to 10¹³).

**Consequence:** zero-shot *function-preserving* size conversion requires **structure-respecting selection maps** (keep/drop heads, hidden units, features — i.e., permutation/selection, which is exactly the **weight-subcloning** family M5 implements as the baseline). Dense learned projections are meaningful as **initializations for brief fine-tuning**, not as drop-in converted models — M5's recovery curves are the right instrument for that comparison, exactly as the plan intended.

**Paper-1 framing:** M2 (representations align, weights don't) + M3 (dense weight projection is far from the target solution *and* functionally broken zero-shot) together sharpen M4's question: is the large residual `W_small − W_hat` *systematically structured* (learnable correction) or noise?

## 5. Bugs found & fixed en route (each with a regression test)

1. **MLP hidden-axis basis rank ceiling** — one weight alone (8192×2048, rank 2048) can't span the 4096-dim target axis; basis now from the joint `[UP, DOWNᵀ]` column-stack (`test_project_model_shapes`).
2. **B_qk stacking axis** — `[Q; K]` row-stack put left singular vectors in the wrong (4096) space; shared *output* bases must column-stack (`test_project_model_shapes`).
3. **`fit_operator` init rank ceiling** — SVD-of-mean warm start silently truncated when target dims exceed the weight rank; QR random-orthonormal fallback added (`test_fit_operator_handles_rank_limited_mlp_shapes`).

`svd_axis_basis` now asserts `k ≤ rank` so misuse fails loudly. Test suite: **16 pass**.
